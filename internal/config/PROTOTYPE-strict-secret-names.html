Should Policies name only defined Secret Names?

A Policy lists Secret Names; the secrets section defines them. Today a Policy may name a Secret Name that isn't defined, and the Agent just gets a 403. This demo runs the same config edits through three validation rules side by side: strict refuses the config, warn accepts it and logs a warning, lenient accepts it silently (today's behavior).

"Apply" boots TrustedCourier the first time and reloads it after that. Reload is planned in #11, where a rejected reload keeps the running config in effect. The Agent holds one Agent Token carrying Policy ci-agent.
