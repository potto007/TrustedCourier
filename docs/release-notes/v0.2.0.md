## Experimental tool-side integrations

v0.2.0 is a normal release. The new Codex CLI and Claude Code integrations are
**experimental**, opt-in Linux/WSL integrations, not a general guarantee that
all agent capabilities or credentials are isolated.

Linux amd64 and arm64 archives include `tc-exec`, `tc-claude-hook`, the public
Claude plugin bundle, and integration guides alongside `tc` and the OpenBao
Backend Plugin. macOS archives include the core and OpenBao plugin only; the
experimental execution integration requires Linux/WSL.

- Codex: FIFO dispatch preserves the command sandbox in the scoped tested
  paths. Read allowlists and disabled outer networking protect the tested
  command path, including a skipped hook. Full-harness coverage and interactive
  approval behavior remain unverified.
- Claude: tested modes passed within the worker scope. Hook rewriting itself
  does not grant permission and is not a fail-closed security boundary for the
  entire harness.
- PTYs, streaming, background execution, and continuation are unsupported.
  Same-identity unsandboxed processes and secrets inside allowed paths are
  outside the verified boundary; worker socket limitations remain.
- Operators must separately configure the broker, runtime profile, resources,
  and scoped Agent Tokens. These packages do not provision or change a service.

Consult the included guides before enabling either integration. Ordinary tools
do not automatically gain credentials; named requests use TrustedCourier Proxy
Delivery under configured Policies. No credentials or deployment state are included in the release archives.
